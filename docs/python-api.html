Python API

MarkItDown() 一行轉換；5 個 convert_* 方法各司其職

基本用法

from markitdown import MarkItDown

md = MarkItDown(enable_plugins=False)   # True 則開啟外掛
result = md.convert("test.xlsx")
print(result.text_content)

回傳值：DocumentConverterResult

  • result.markdown — 原始 Markdown 字串
  • result.text_content — 與 markdown 同義的別名（歷史命名）
  • result.title — 文件標題（部分 converter 會填，如 EPUB）

5 個 convert_* 方法

方法輸入何時用
convert()str 路徑/URL、Path、requests.Response、BinaryIO最通用，自動分派到下面四個
convert_local()本機檔案路徑只處理本機檔案（最窄、最安全）
convert_stream()BinaryIO（bytes 流）你已 open 一個 stream，且不需要本地路徑
convert_uri()file: / data: / http: / https: URI從 URI 讀取（含網址）；convert_url() 是它的別名
convert_response()requests.Response你自己控制 HTTP 請求（proxy、驗證、快取…），再把 response 交給它
安全建議：官方文件明確建議「只用最窄的 convert_* 函數」。 若你的應用只需要讀本機檔案，就用 convert_local()；需要控制抓取就自己 requests.get() 再 convert_response()。詳見安全模型。

StreamInfo（線索卡）

當來源缺少副檔名/MIME 線索（例如裸 stream），可以手動提供 stream_info 提示：

from markitdown import StreamInfo

md = MarkItDown()
result = md.convert_stream(
    my_bytes_io,
    stream_info=StreamInfo(extension=".docx", mimetype="application/vnd.openxmlformats-officedocument.wordprocessingml.document"),
)

CLI 的 -x / -m / -c 旗標背後就是建一個 StreamInfo。

LLM 圖片描述（pptx / 圖片）

from markitdown import MarkItDown
from openai import OpenAI

client = OpenAI()
md = MarkItDown(
    llm_client=client,
    llm_model="gpt-4o",
    llm_prompt="optional custom prompt",   # 預設 "Write a detailed caption for this image."
)
result = md.convert("example.jpg")
print(result.text_content)

任何 OpenAI 相容 client 都行（OpenAI、AzureOpenAI、本地 OpenAI-compatible server）。

外掛 + OCR

md = MarkItDown(enable_plugins=True, llm_client=OpenAI(), llm_model="gpt-4o")
result = md.convert("document_with_images.pdf")

詳見外掛系統與 OCR 套件源碼。

概念解說

MarkItDown 的 Python API 提供 5 個 convert_* 方法，從最通用到最窄： convert()（自動分派）、convert_local()（本機檔案）、 convert_stream()（位元組流）、convert_uri()（URI/URL）、 convert_response()（requests.Response）。官方建議只用最窄的方法—— 縮小攻擊面、避免意外的網路或檔案系統存取。

回傳值 DocumentConverterResult 有三個欄位：markdown（原始 Markdown）、 text_content（同義別名）、title（部分 converter 會填）。

實際操作 Worked Example

步驟 1：基本本機轉換

from markitdown import MarkItDown

md = MarkItDown()
result = md.convert_local("report.pdf")
print(result.markdown[:200])  # 前 200 字元

步驟 2：從 URL 轉換（控制 HTTP 請求）

import requests
from markitdown import MarkItDown

md = MarkItDown()
resp = requests.get("https://example.com", headers={"User-Agent": "MyApp/1.0"})
result = md.convert_response(resp)
print(result.text_content)

步驟 3：帶 LLM 圖片描述

from markitdown import MarkItDown
from openai import OpenAI

client = OpenAI()
md = MarkItDown(llm_client=client, llm_model="gpt-4o")
result = md.convert("photo.jpg")
print(result.text_content)  # 含 EXIF + LLM 描述

常見錯誤與除錯

PermissionError: [Errno 13]
使用 convert() 時，它會嘗試多種方式（本機/URI）。改用 convert_local() 可避免意外的網路嘗試。
convert_uri() 超時
預設無 timeout。建議自己 requests.get(timeout=30) 後用 convert_response()。
StreamInfo 提示：
當 stream 缺少副檔名線索時，手動建立 StreamInfo(extension=".docx") 可大幅提升格式偵測準確度。

練習與驗收

  1. 用 convert_local() 轉換一個 DOCX，再用 convert() 轉換同一檔案，比較結果。
  2. 寫一個腳本：從 stdin 讀取 bytes，用 convert_stream() + StreamInfo 轉換。
  3. 故意傳入不存在的檔案路徑，觀察例外類型與錯誤訊息。

① 進階真實情境：受控 HTTP 抓取 + 批次轉換 + 品質驗證服務

場景：你寫一個內部「文件轉換服務」，接收一批 URL，要轉成 Markdown 存進索引。 關鍵需求：自己控制 HTTP 請求（設定 UA、timeout、proxy），再用 convert_response() 轉換——這正是安全守則的第二條。

import requests
from markitdown import MarkItDown

def fetch_and_convert(urls, timeout=30, headers=None):
    md = MarkItDown()
    session = requests.Session()
    session.headers.update(headers or {"User-Agent": "DocIngest/1.0"})
    results = []
    for url in urls:
        resp = session.get(url, timeout=timeout)
        resp.raise_for_status()                 # 401/404 直接失敗，別轉錯誤頁
        try:
            text = md.convert_response(resp).markdown
            ok = len(text.strip()) >= 100       # 品質閘
        except Exception as e:                  # FileConversionException 等
            text, ok = f"[ERROR] {e}", False
        results.append({"url": url, "ok": ok, "chars": len(text)})
    return results

# 服務入口：只吃白名單 scheme（防 SSRF）
from urllib.parse import urlparse
def safe_convert(url):
    if urlparse(url).scheme not in ("http", "https"):
        raise ValueError("only http/https allowed")
    return fetch_and_convert([url])

為什麼選這條路徑：convert_response() 是「你抓、它轉」的契約—— HTTP 細節（UA、驗證、proxy、timeout、重試）由你掌控，MarkItDown 只負責讀 response 轉換。 配上 raise_for_status() 與字數品質閘，把「抓錯頁面」與「掃描假成功」都擋在進索引之前。

② 深入原理擴充：convert() 的「自動分派」其實是四條路線

convert(source) 是方便的總入口，但它背後是依輸入型別分派的四個不同路徑：

  • str：以 http:/https:/file:/data: 前綴判斷走 convert_uri，否則 convert_local。
  • Path：直接 convert_local。
  • requests.Response：走 convert_response。
  • 有 .read() 的 bytes 流：走 convert_stream。
大家以為轉換沒問題但其實丟資訊
convert_uri() 對 file: URI 的 netloc（主機名）有驗證——非 localhost 會拋 ValueError。 但很多人不知道 data: URI 的圖片預設會被截斷：![image](data:image/png;base64,.....) 長到一個門檻就會被 _markdownify 截短，僅剩一段前綴——圖片「轉換成功」但實際內容被丟掉。 要保留需用 --keep-data-uris 或自行處理 data URI。

③ 診斷式疑難排解表

症狀可能原因解決方案
convert() 對網路 URL 一直超時內部抓取無 timeout改用 requests.get(timeout=30) + convert_response()
轉到 404 / 登入頁卻「成功」沒 raise_for_status()，錯誤頁被當 HTML 轉了抓取後先 resp.raise_for_status()
純文字 stream 猜錯格式stream 沒副檔名/MIME 線索手動 stream_info=StreamInfo(extension=..., mimetype=...)
圖片轉出截斷的 data URI預設截斷長 base64用 --keep-data-uris 或後處理恢復完整 URI
TypeError: unsupported type傳入非 str/Path/Response/BinaryIO確認型別；若已有 bytes 請包成 io.BytesIO

④ 進階挑戰題

  1. 用 convert_response() 實作一個「帶重試與退避」的抓取器：失敗重試 3 次、指數退避，最後才把失敗記錄下來。
  2. 寫一個函數：接收任意型別（str/Path/Response/BytesIO），統一轉成 StreamInfo 提示後呼叫對應的 convert_* 方法。
  3. 測試 convert_stream() 對「不可 seek 的串流」（如 socket 包裝）如何處理——它會先讀成 BytesIO，驗證此行為。
