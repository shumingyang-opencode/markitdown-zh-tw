外掛系統

MarkItDown 用 Python entry-point 讓第三方擴充「安裝即註冊」，預設關閉

運作方式

  1. 外掛套件在 pyproject.toml 宣告 entry-point：[project.entry-points."markitdown.plugin"]。
  2. 套件匯出 __plugin_interface_version__ 與 register_converters(markitdown, **kwargs)。
  3. 每次建立 MarkItDown 實例時，若 enable_plugins=True（或 CLI --use-plugins）， 會 entry_points(group="markitdown.plugin") 載入全部已安裝外掛，呼叫 register_converters()。
  4. 外掛可用 register_converter(converter, priority=...) 在任何優先級插入 converter——包括搶在內建 converter 之前。

外掛預設關閉

# 列出已安裝外掛
markitdown --list-plugins

# 使用外掛
markitdown --use-plugins path-to-file.pdf

# Python API
md = MarkItDown(enable_plugins=True)
result = md.convert("path-to-file.rtf")
注意：外掛載入失敗（entry_point.load() 拋例外）不會中斷， 只會 warn() 並跳過——所以裝了外掛但沒生效時，先檢查 --list-plugins。

官方外掛：markitdown-ocr

用 LLM Vision 抽取 PDF、DOCX、PPTX、XLSX 中「內嵌圖片」的文字（OCR）， 不需要新 ML 函式庫——沿用核心既有的 llm_client / llm_model 模式。

pip install markitdown-ocr
pip install openai

markitdown document.pdf --use-plugins --llm-client openai --llm-model gpt-4o

重點行為：

  • 四個 OCR 增強 converter 以 priority -1.0 註冊——在內建（0.0）之前。
  • 掃描版 PDF（無文字層）自動整頁渲染 300 DPI 送 LLM。
  • OCR 區塊包成 *[Image OCR]...<文字>[End OCR]*，就地插入不破壞文件流程。
  • 沒有 llm_client 時外掛仍載入但「靜默略過」，退回內建 converter。

概念解說

MarkItDown 的外掛系統基於 Python entry-point 機制。 外掛套件在 pyproject.toml 宣告 [project.entry-points."markitdown.plugin"]， 匯出 register_converters(markitdown, **kwargs) 函數。 每次建立 MarkItDown(enable_plugins=True) 時，會自動載入所有已安裝外掛。

外掛可以在任何 priority 註冊 converter——包括負值（搶在內建之前）或正值（兜底之後）。 這讓 markitdown-ocr 能以 priority -1.0 在內建 PDF/DOCX converter 之前攔截，注入 OCR 增強。

常見錯誤與除錯

外掛裝了但沒生效
執行 markitdown --list-plugins 確認外掛是否被偵測。若不在清單中，檢查 pyproject.toml 的 entry-point 宣告。
OCR 外掛靜默略過
沒有 llm_client 時，OCR 外掛仍載入但「靜默略過」——退回內建 converter。不會報錯，但也沒有 OCR 增強。

練習與驗收

  1. 安裝 markitdown-sample-plugin，用 --list-plugins 確認。
  2. 閱讀 sample-plugin 的 register_converters()，理解外掛如何插入 converter。
  3. 故意移除 entry-point 宣告，觀察外掛消失的行為。

① 進階真實情境：自建 .rtf 外掛 + priority 攔截 + 打包發佈

場景：公司內部有大量 RTF 合約，MarkItDown 內建不支援。你要寫一個外掛補上， 並確保它優先於兜底 converter——否則 RTF 會被 PlainTextConverter 當純文字「成功」轉出。

# my_rtf_plugin.py
from markitdown import MarkItDown
from markitdown._base_converter import DocumentConverter, DocumentConverterResult
from markitdown import StreamInfo

class RtfConverter(DocumentConverter):
    def accepts(self, file_stream, stream_info: StreamInfo, **kwargs) -> bool:
        return stream_info.extension == ".rtf" or stream_info.mimetype == "application/rtf"
    def convert(self, file_stream, stream_info, **kwargs) -> DocumentConverterResult:
        raw = file_stream.read().decode("cp1252", errors="replace")  # RTF 是控制碼文字
        text = strip_rtf_control(raw)  # 簡化：剝掉 {\rtf...} 控制字
        return DocumentConverterResult(markdown=text)

def register_converters(markitdown: MarkItDown, **kwargs):
    # priority=-1.0 搶在 PlainText(10.0)/Html(10.0) 之前
    markitdown.register_converter(RtfConverter(), priority=-1.0)

__plugin_interface_version__ = 1
# pyproject.toml（打包成可 pip 安裝的套件）
# [project.entry-points."markitdown.plugin"]
# my_rtf_plugin = "my_rtf_plugin"

為什麼選這條路徑：外掛系統的設計就是「安裝即註冊、priority 控制優先序」。 用負 priority 讓 RTF 專屬 converter 搶在通用兜底之前；打包成 pip 套件後， 團隊成員只要 pip install my-rtf-plugin 就能生效，不需要改核心程式。

② 深入原理擴充：外掛載入的「lazy 快取」與 priority 攔截

外掛機制有三個容易被忽略的內部行為：

  • lazy 快取：_load_plugins() 用模組級全域 _plugins 記快取， 第一次呼叫才真的 entry_points(group="markitdown.plugin")—— 同一個 process 內改外掛程式碼不會立刻生效。
  • 單一外掛壞了不拖垮全部：單一 plugin 的 load() 拋例外只 warn() 並跳過。
  • register_converter 用 insert(0, ...)：後註冊者排前面，搭配穩定排序決定同 priority 的嘗試順序。
大家以為轉換沒問題但其實丟資訊
OCR 外掛的「靜默略過」是最常被誤解的：沒有 llm_client 時， markitdown-ocr 的四個增強 converter 仍會載入，但 convert() 內部靜默退回內建行為—— 不會報錯、不會警告。你以為「開了外掛就有 OCR」，其實掃描 PDF 的圖片文字從頭到尾都沒被抽取， 輸出「正常」但資訊缺了一整層。

③ 診斷式疑難排解表

症狀可能原因解決方案
--list-plugins 看不到外掛entry-point 沒宣告或套件沒安裝檢查 pyproject.toml 的 [project.entry-points."markitdown.plugin"]
外掛載入但從不執行未設 enable_plugins=True / 未加 --use-plugins開旗標；外掛預設關閉是設計行為
OCR 外掛沒抽到圖片文字缺 llm_client/llm_model，靜默略過提供 OpenAI client + model；確認輸出含 [Image OCR] 區塊
自己的 converter 順序不對priority 設錯負值保證在內建(0.0)之前；印出 md._converters 確認
改外掛程式碼但行為沒變lazy 快取已載入重啟 process；或直接呼叫 _load_plugins.cache_clear()（如有）

④ 進階挑戰題

  1. 實作完整的 RtfConverter（含真正的 RTF 控制碼剝除），寫測試驗證 accepts() 對 .rtf 與 text/rtf 都回 True。
  2. 設計兩個外掛：一個 priority=-1.0、一個 priority=10.0，同時處理同一個格式，驗證誰先被嘗試。
  3. 追蹤「外掛載入失敗」的容錯行為：讓你的外掛在 register_converters 拋例外，確認主程式不中斷。
