案例：PDF + 網頁/網址

PDF（中文+表格）、HTML、CSV、JSON——真實工具輸出，本站實跑
markitdown 0.1.7 · 對齊 fd239d5

1. PDF（report.pdf）

輸入為 reportlab 產出的測試報告（STSong 中文字型 + 表格）。輸出由 pdfminer 抽取文字—— 觀察到「抽取順序」不一定是視覺順序（內文先於標題），表格以逐格換行呈現而非 Markdown 表格。 這是 pdfminer 版面分析的固有特性，也是 PDF 轉換的主要限制之一。

這是一份用來示範 PDF 轉換的報告，包含標題、段落與表格。

MarkItDown 測試報告

markitdown worked/conversions/pdf/report.pdf -o worked/conversions/pdf/report.md
重點：PDF 沒有「語意結構」可言——MarkItDown 只能盡量從版面猜。 需要高品質 PDF 抽取（掃描檔、複雜表格）時，官方建議改用 Azure Content Understanding（見雲端頁）。

2. HTML（example.html）

標題、連結列表、表格都完整保留，是 MarkItDown 最擅長的格式之一。

3. CSV（data.csv）

| name | role | city |
| --- | --- | --- |
| Alice | Engineer | Taipei |

markitdown worked/conversions/web/data.csv -o worked/conversions/web/data-csv.md

4. JSON（data.json）

JSON 沒有對應的專用 converter——落到 PlainTextConverter，輸出為縮排後的程式碼區塊。

{
  "project": "markitdown-zh-tw",
  "versions": [
    0,
    1,
    7
  ],
  "tags": [
    "markdown",
    "llm"
  ]
}
markitdown worked/conversions/web/data.json -o worked/conversions/web/data-json.md

5. 網址（直接餵 URL）

不需要先下載——convert_uri 直接抓取。真實輸出見 dogfood 案例頁 （轉 GitHub 頁、PyPI 頁、raw README）。

重現方式

markitdown worked/conversions/pdf/report.pdf   -o worked/conversions/pdf/report.md
markitdown worked/conversions/web/example.html -o worked/conversions/web/example.md
markitdown worked/conversions/web/data.csv     -o worked/conversions/web/data-csv.md
markitdown worked/conversions/web/data.json    -o worked/conversions/web/data-json.md
