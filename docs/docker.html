Docker

不污染本機 Python 環境，一行指令把檔案丟進容器轉換

建映像與使用

# 從 repo 根目錄（含 Dockerfile）建映像
docker build -t markitdown:latest .

# stdin 管道轉換
docker run --rm -i markitdown:latest < ~/your-file.pdf > output.md

docker 版本非常適合：不想在本機裝 Python 依賴、或需要乾淨隔離（配合外掛/多版本）的場景。

markitdown-mcp 的 Docker 用法

# 建映像
docker build -t markitdown-mcp:latest .

# 啟動（遠端 URI 即可，本機檔案需掛載）
docker run -it --rm markitdown-mcp:latest

# 掛載本機目錄：容器內以 /workdir 存取
docker run -it --rm -v /home/user/data:/workdir markitdown-mcp:latest

搭配 Claude Desktop

{
  "mcpServers": {
    "markitdown": {
      "command": "docker",
      "args": ["run", "--rm", "-i", "-v", "/home/user/data:/workdir", "markitdown-mcp:latest"]
    }
  }
}
安全提示：容器預設無法存取本機檔案；掛載目錄等於把該路徑開放給容器內程序。 只掛載需要的目錄，並注意 markitdown-mcp 無認證機制。

概念解說

Docker 模式的核心價值是環境隔離：不污染本機 Python 環境， 所有依賴（pdfminer、mammoth、openpyxl…）都封裝在容器映像中。 適用場景：(1) 不想在本機裝依賴、(2) 需要乾淨隔離（配合外掛/多版本）、 (3) CI/CD 管線中使用。

容器預設無法存取本機檔案——需要掛載目錄（-v）才能讀寫。

實際操作 Worked Example

步驟 1：建映像

# 從 repo 根目錄（含 Dockerfile）建映像
docker build -t markitdown:latest .

步驟 2：轉換本機檔案（stdin 管道）

# 用 stdin 管道把 PDF 送進容器
docker run --rm -i markitdown:latest < report.pdf > report.md

# 或掛載目錄
docker run --rm -v $(pwd):/workdir markitdown:latest \
  markitdown /workdir/report.pdf -o /workdir/report.md

步驟 3：markitdown-mcp Docker

# 啟動 MCP server
docker run -it --rm -v $(pwd):/workdir markitdown-mcp:latest

常見錯誤與除錯

容器內找不到檔案
確認 -v 掛載路徑正確。容器內以掛載點為根目錄存取，不是本機路徑。
映像建置失敗
確認 Dockerfile 在 repo 根目錄。常見問題：Docker daemon 未啟動、磁碟空間不足。

練習與驗收

  1. 建好映像後，用 docker run --rm markitdown:latest markitdown --help 確認 CLI 可用。
  2. 掛載一個目錄，轉換其中的 PDF，確認輸出寫回掛載點。
  3. 用 docker images | grep markitdown 確認映像大小。
