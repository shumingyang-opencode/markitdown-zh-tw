五大家族重點

Office：DOCX / XLSX / PPTX

  • DOCX：經 mammoth 轉 HTML 再轉 Markdown；converter_utils/docx/ 先把 OMML 數學轉成 LaTeX。
  • XLSX：pandas 讀取，每個工作表輸出 ## 工作表名 + Markdown 表格。
  • PPTX：每張投影片輸出 <!-- Slide number: N --> 註解 + 標題 + 項目 + 表格。

PDF

  • pdfminer.six 負責文字抽取、pdfplumber 負責表格。
  • 後處理把 MasterFormat 風格的「部分編號」(.1 / .2…) 與下一行合併。
  • 掃描版（無文字層）或複雜版面是已知限制。

Web / 網址

  • HTML / RSS / Wikipedia / YouTube / Bing SERP 都可以直接餵 URL（convert_uri）。
  • HTTP 請求會帶 Accept: text/markdown, text/html;q=0.9...，若伺服器支援先給 Markdown。

Media：圖片 / 音訊

  • 圖片：EXIF（需 exiftool）+ LLM 描述（需 llm_client/llm_model，multimodal）。
  • 音訊：EXIF（需 exiftool）+ 轉錄（需 SpeechRecognition，預設 Google API）。
  • 兩者「依賴式輸出」——缺工具就少一段內容（或失敗），見媒體案例。

封裝：ZIP / EPUB / CSV / JSON / iPython / Outlook

  • ZIP：解壓到暫存目錄、依副檔名遞迴轉換每一檔、保留結構，結束清理。
  • EPUB：解析 container.xml → content.opf → spine，逐章用 HtmlConverter 轉。
  • CSV：直接轉 Markdown 表格；JSON：縮排成程式碼區塊（PlainText）。

概念解說

22 個轉換器可按輸入來源分為五大家族： Office（DOCX/XLSX/PPTX）、PDF、Web（HTML/RSS/Wikipedia/YouTube/Bing SERP）、 Media（圖片/音訊）、封裝（ZIP/EPUB/CSV/Outlook/Jupyter）。 每個 converter 實作兩個方法：accepts() 判斷是否能處理（通常看 mimetype/extension）， convert() 執行實際轉換。

priority 決定嘗試順序：特定格式 converter 為 0.0， 兜底的 PlainText/Html/Zip 為 10.0。外掛可用負值（如 OCR 的 -1.0）搶先內建。

實際操作 Worked Example

步驟 1：依格式挑 converter

# PDF → PdfConverter（依賴 pdfminer.six + pdfplumber）
markitdown report.pdf -o report.md

# XLSX → XlsxConverter（依賴 pandas + openpyxl）
markitdown data.xlsx -o data.md

# 網頁 URL → HtmlConverter（依賴 beautifulsoup4）
markitdown https://example.com -o page.md

步驟 2：觀察輸出差異

# PDF：文字 + 表格（MasterFormat 合併）
# XLSX：每工作表一個 ## 標題 + Markdown 表格
# HTML：標題/清單/連結/表格結構保留

步驟 3：測試兜底 converter

# 沒有對應 converter 的格式會 fallback 到 PlainTextConverter
echo '{"key":"value"}' | markitdown -x .json

常見錯誤與除錯

PDF 表格抽取不完整
pdfplumber 對複雜合併儲存格或掃描版 PDF 效果有限。嘗試用 Azure Document Intelligence（-d 旗標）取得更好結果。
XLSX 輸出缺少格式
XlsxConverter 只抽取文字和數字，不保留儲存格格式、公式結果、圖表。這是設計取捨——專注於「可 LLM 消化的純文字」。
YouTube 字幕為空
YouTubeConverter 依賴 youtube-transcription 套件。若影片無字幕或字幕被關閉，輸出只含標題和描述。

練習與驗收

  1. 準備一份有合併儲存格的 XLSX，觀察 Markdown 表格如何處理合併格。
  2. 找一個有掃描圖片的 PDF，比較本地轉換與 Azure Document Intelligence 的差異。
  3. 用 echo "hello" | markitdown -x .xyz 測試未知格式的 fallback 行為。

① 進階真實情境：批次處理異質文件庫 + 品質抽樣 + 外掛補強

場景：你的公司有一個混雜的文件庫——DOCX 合約、掃描 PDF、XLSX 報表、PPTX 簡報混在一起。 目標是全部轉成 Markdown 進 RAG。因為格式混雜，品質不能一視同仁：每個格式要各自的驗證閘。

from pathlib import Path
from markitdown import MarkItDown
from markitdown._exceptions import FileConversionException

md = MarkItDown()
rules = {
    ".docx": lambda t: t.count("#") >= 1,          # 標題結構
    ".xlsx": lambda t: t.count("|") >= 3,          # 至少一張表
    ".pdf":  lambda t: len(t) > 200,              # 掃描 PDF 會掛在這
    ".pptx": lambda t: "Slide number" in t,
}

for path in Path("docs/").rglob("*"):
    if path.suffix not in rules:
        continue
    try:
        text = md.convert_local(str(path)).markdown
        status = "PASS" if rules[path.suffix](text) else "LOW-Q"
    except FileConversionException as e:
        status = f"FAIL ({e.attempts[0].converter.__class__.__name__})"
    print(f"{status:>22}  {path}")

為什麼選這條路徑：每個 converter 的輸出結構不同（DOCX 有標題、XLSX 有表格、PPTX 有 Slide 註解）， 所以驗證閘必須格式特定；只對標的格式設閘，其他格式不重複處理。 把「失敗的 converter 名稱」直接印出來，是定位問題最快的線索。

② 深入原理擴充：三條「表格解析」之路

「把資料結構轉成 Markdown 表格」在 MarkItDown 裡至少有三條不同技術路線：

  • CSV：csv.Sniffer 猜分隔符（逗號/分號/Tab…），首列當表頭，直接輸出 | a | b |。
  • PDF：先試 pdfplumber page.extract_tables()；無邊框表格退回 _extract_tables_from_words()——用 word 的 x/y 座標聚類成欄與列。
  • XLSX：pandas 讀整張表（含合併列、註解文字），NaN 代表空值。
大家以為轉換沒問題但其實丟資訊
XLSX 的合併儲存格是最典型的例子：pandas 會把合併格「展開」， 但只有左上角有值，其餘是 NaN。你看到表格「轉換成功」， 但原本一眼就能看出來的「橫跨三欄的總計列」在 Markdown 裡變成一行 NaN——資訊被結構性地丟掉。 同理 PDF 的複雜合併格、PPTX 圖片若無 llm_client 只有 ![image](...) 沒有描述。

③ 診斷式疑難排解表

症狀可能原因解決方案
CSV 轉成表格但欄位全錯csv.Sniffer 猜錯分隔符檢查檔案分隔符；必要時先預處理成標準 CSV
PDF 表格缺列或缺格合併儲存格、無邊框表格用 pdfplumber word 座標重組，或改用 Azure Document Intelligence
XLSX 出現大量 NaN空儲存格、合併格展開轉換後過濾 NaN；確認合併格語意是否可接受
YouTube 字幕輸出為空影片無字幕或缺 youtube-transcriptionpip install 'markitdown[youtube-transcription]'；確認影片有開啟字幕
PPTX 圖片只有檔名沒有描述未設定 llm_client/llm_model傳入 OpenAI client 與模型；沒 LLM 就只能接受無描述

  3. 設計一個自訂 converter：把 .csv 但分隔符是 pipe（|）的檔案正確轉成 Markdown 表格。
